# Легенда проекта «6 минут. Дневник успеха» — для людей и нейросетей

Прочитай этот файл целиком, прежде чем что-то менять. Он описывает, что это за приложение, как оно устроено и какие правила нельзя нарушать.

## 1. Что это

Личное веб-приложение (PWA) для одного пользователя — Рината. Это цифровая копия **рабочих страниц** бумажного ежедневника «6 минут. Дневник успеха» (Доминик Спенст, издательство «Альпина»; оригинал — «Das 6-Minuten Erfolgsjournal», UrBestSelf). Теоретическая часть книги в приложение не переносится.

Используется на iPhone: открывается из Safari и добавляется на экран «Домой», работает без интернета. На Mac открывается по тому же адресу.

Адрес приложения: https://rinakzhigitov95-crypto.github.io/6min-dnevnik/
Код: https://github.com/rinakzhigitov95-crypto/6min-dnevnik (публичный, только код).
Записи: https://github.com/rinakzhigitov95-crypto/6min-dnevnik-data (приватный, только данные).

## 2. Жёсткие требования пользователя (не нарушать)

1. **Записи никогда не теряются и не перетираются.** Нет кнопки удаления. Любая правка сохраняет прежнюю версию в историю. Синхронизация не затирает более свежую версию старой.
2. **Бесплатно и без лишних сервисов.** Только GitHub (Pages + приватный репозиторий). Никаких бэкендов, Firebase, Supabase, платных аккаунтов, аккаунта разработчика Apple.
3. **Один сервис, целостно.** Всё внутри одного приложения.
4. **Без напоминаний и уведомлений.** Пользователь заходит сам.
5. **Структура и тексты полей — как в книге.** Заголовки, подписи и порядок блоков повторяют бумажный ежедневник (см. раздел 5). Не «улучшать» формулировки.
6. **Интерфейс на русском.** Оформление «под бумагу»: кремовый фон, пунктирные строки, серифные заглавные заголовки с разрядкой, золотой акцент.
7. **Без сборки.** Чистые HTML/CSS/JS, никаких npm, бандлеров, фреймворков. Файлы правятся напрямую.
8. Приложение не размещается рядом с личным сайтом rinakzhigitov.ru (решение пользователя).

## 4. Как устроено приложение (app.js)

Одностраничное приложение на хеш-роутере. Маршруты:

| Хеш | Экран | Функция |
|---|---|---|
| `#/day/YYYY-MM-DD` | День | `viewDay` |
| `#/week/YYYY-MM-DD` (понедельник) | Неделя | `viewWeek` |
| `#/month/YYYY-MM` | Месяц (план + ежемесячная оценка) | `viewMonth` |
| `#/triad` или `#/triad/<дата старта>` | Триада (этап) + OKR | `viewTriad` |
| `#/review/<дата старта триады>` | Промежуточный обзор этапа | `viewReview` |
| `#/settings` | «Ещё»: копии, GitHub, о приложении | `viewSettings` |

`render()` читает хеш, вызывает функцию экрана (async, возвращает DOM-узел), заменяет содержимое `#app` и нижнюю навигацию. DOM строится помощником `h(tag, attrs, ...children)`. Поля ввода: `line()` — однострочное поле с пунктирным низом, `area()` — авторастущий textarea с «линейками», `check()` — кружок-чекбокс, `taskRow()` — чекбокс + строка.

**Автосохранение.** Любой ввод вызывает `save(key, obj)` → через 400 мс `flush(key)` → `Store.put`. Перед записью в объект ставится `updatedAt` (ISO). При уходе со страницы/сворачивании вызывается `flushAll()`. Статус «Сохранено» показывается в правом верхнем углу (`setStatus`).

**Enter** в однострочном поле переводит фокус на следующее поле.

## 5. Модель данных (IndexedDB `dnevnik6`, версия 2)

Хранилища:
- `entries` — записи по строковому ключу.
- `history` — каждая ПРЕЖНЯЯ версия записи при изменении: `{key, at, data}`. Никогда не чистится.
- `sync` — служебное: `sha:<key>` (sha файла в GitHub), `dirty:<key>` (ждёт отправки), `lastSync`.

Ключи и формы записей (`DEF` в app.js):

- `day:YYYY-MM-DD` — `{gratitude[3], anticipate[3], focus, cream[2]{t,done}, cherries[5]{t,done}, deadlines, fun[3]{t,done}, evening}`.
  Экран дня (как в книге): полоса Пн…Вс с обведённым днём и дата → «Я благодарю» ×3 / «Я предвкушаю» ×3 → рамка «Фокус дня. Пирожное — чему я порадуюсь и что прибавит мне сил» + «Сделана отметка в трекере привычек?» (живые галочки привычек этой недели, пишутся в запись недели) → «Список дел»: «Сливки» ×2, «Вишенки» ×5, «Сроки и комментарии» → «Список развлечений» ×3 → полоса с цитатой дня → «Мысли, идеи и достижения».
- `week:YYYY-MM-DD` (дата понедельника) — `{events[6], notes, habits[5]{name, days[7]}, goals[2]{title, steps[3]{t,done}}, meaning, progress}`.
  Экран: «План на неделю»: «Даты и события» (Пн, Вт, Ср, Чт, Пт, Сб/Вс) → «Заметки и идеи» → «Трекер привычек» 5×7 → «Фокус недели» (Цель 1, Цель 2 по 3 шага) → «Размышления о себе»: «Осмысленность и мотивация», «Успехи и прогресс».
- `month:YYYY-MM` — `{notes{1..31: строка}, pride[3], ratings{id: 1..10|null}, progress}`.
  Экран: «План на месяц» — 31 строка с полем события, золотая точка у дней, где есть запись дня, подсветка сегодня; название месяца сверху = выбор месяца (`input type=month`), стрелки листают. Ниже «Ежемесячная оценка»: «Успехи месяца» (3), «Ежемесячная проверка» — 15 шкал 1–10 (список `RATINGS`), «Прогресс».
- `triad:YYYY-MM-DD` (дата старта) — `{start, end, value, goals[3], habits[3], okrs[]{objective, krs[]{t, progress 0..100}}}`.
  Этап по умолчанию 3 месяца (`end = start + 3 мес − 1 день`), опция «66 дней, как в книге». Экран: «Моя триада»: ценность (1), цели (3), привычки (3), затем «Цели на этап · OKR» (Objective + Key Results с ползунком, процент цели = среднее по заполненным KR). Кнопки: «Промежуточный обзор», «Начать новую триаду». Старые этапы остаются в списке.
- `review:<дата старта триады>` — `{triad, date, value, answers[5]: 'yes'|'no'|null, notes}`.
  Экран «Промежуточный обзор»: ценность за этап, «Пройдена половина пути» — 5 утверждений (`STATEMENTS`) с «Да, очень»/«Нет», итог по OKR, «Мысли».
- `meta:settings` — `{startDate, created}` (сейчас почти не используется).
- `meta:github` — `{token, repo, branch, api}`. **Никогда не попадает в экспорт и не синхронизируется.**

Проверка «день заполнен»: `dayHasContent` — есть хоть один непустой текст.

## 6. Копия в GitHub (модуль `GH` в app.js)

- Записи с ключами `day|week|month|triad|review` синхронизируются в приватный репозиторий как файлы `<тип>/<id>.json` (например `day/2026-11-06.json`) через GitHub REST API (Contents API, `PUT /repos/{repo}/contents/{path}`). Каждое сохранение — коммит, поэтому история в репозитории полная.
- Доступ: fine-grained personal access token **только** на репозиторий `6min-dnevnik-data` с правом *Contents: Read and write*. Токен вводится в разделе «Ещё» и лежит в `meta:github` в IndexedDB устройства.
- Отправка: при сохранении ключ помечается `dirty:`, через 3 с `push()` отправляет все грязные записи. Если sha не совпал (409/422) — читается версия из репозитория; побеждает та, у которой `updatedAt` новее; проигравшая локальная версия всё равно остаётся в `history`.
- Получение: `pull()` при открытии, при возврате в приложение и при появлении сети — сравнивает sha дерева ветки с сохранёнными и забирает изменившиеся файлы; локальная несинхронизированная правка не затирается более старой удалённой.
- Офлайн: всё работает из IndexedDB, отправка откладывается.
- Файлы в репозитории, не подходящие под шаблон (README.md и т. п.), игнорируются.
- Поле `api` в `meta:github` позволяет направить запросы на локальную имитацию (`tools/mock-github.py`, токен `test-token`) — только для тестов.

## 7. Сервис-воркер и обновления

`sw.js` кэширует файлы приложения (`FILES`) и отдаёт их офлайн; в сети сначала кэш, затем обновление из сети. **При любом изменении файлов в `app/` увеличивай `VERSION` в sw.js**, иначе у пользователя останется старая версия. Данные записей в сервис-воркере не кэшируются.

## 8. Цитаты дня (`app/quotes.js`)

`window.QUOTES` — массив из 365 объектов `{text, author}`. Цитата выбирается по номеру дня в году (1 января — первая, `quoteFor` в app.js), поэтому порядок в файле = календарь. Пользователь хочет **настоящие цитаты известных людей с указанием автора**. Пустой `author` допустим (строка автора тогда не показывается), но нежелателен.

## 9. Резервные копии

Раздел «Ещё»: «Сохранить копию (JSON)» — файл `6min-dnevnik-<дата>.json` со всеми записями и историей (без токена), через системное «Поделиться» (можно положить в iCloud Drive). «Восстановить из копии» — импорт с подтверждением; записи после импорта уходят в GitHub.

## 10. Публикация и проверка

- Деплой: `git push` в `main` → GitHub Actions (`pages.yml`) выкладывает папку `app/` на GitHub Pages. Pages настроен в режиме `workflow`.
- Локально: `python3 -m http.server 8765 --directory app` или конфигурация `dnevnik` из `.claude/launch.json`, затем http://localhost:8765. Проверяй в мобильном размере (375×812).
- Если в браузере не видно изменений — сними регистрацию сервис-воркера и очисти кэш (DevTools → Application), либо увеличь `VERSION`.
- Проверка синхронизации без настоящего токена: `python3 -I tools/mock-github.py 8766`, затем в консоли приложения `Store.put('meta:github', {token:'test-token', repo:'test/data', branch:'main', api:'http://localhost:8766'})` и перезагрузка.

## 11. Особенности iOS, о которых легко забыть

- Размер шрифта в полях ввода не меньше 16px — иначе Safari приближает страницу.
- Отступы под «чёлку» и индикатор снизу: `env(safe-area-inset-*)`, `viewport-fit=cover`.
- Приложение с экрана «Домой» и вкладка Safari — это **разные** хранилища IndexedDB. Токен и записи надо вводить в той версии, которой пользуешься (с экрана «Домой»).
- `navigator.storage.persist()` вызывается при старте, чтобы iOS не стирала данные при нехватке места.
- Push-уведомления не используются и не нужны.
